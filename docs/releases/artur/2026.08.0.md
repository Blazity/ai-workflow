# AI Workflow — 2026.08.0

## Highlights

The headline of this release is a completely new visual workflow editor: you compose how the agent works from connected blocks, with branching, parallel steps, first-class prompts and output schemas, guided migration and visual replay of runs. Alongside it: versioned Harness Profiles, runs that span multiple repositories, agent memory, and automated review cycles after the pull request. Underneath, a long list of reliability fixes makes run statuses truthful and the platform steadier under load.

## What's new

### A new visual workflow editor

- Build workflows from blocks with typed data connections: triggers (Jira, GitHub, GitLab), Branch with plain AND/OR conditions and typed outcomes, Transform with seven ready-made data operations, and branchable Run Checks and Pre-PR Checks.
  <!-- sources: 136,156 -->
- Fan out into parallel steps and join the results back together.
  <!-- sources: 136,172 -->
- Write prompts in a rich editor with validated Prompt Slots and drag-in content from the prompt library; an effective-prompt view shows exactly what the agent receives.
  <!-- sources: 136,155 -->
- Define each agent's output shape in a schema editor, visual or raw JSON Schema.
  <!-- sources: 135,136 -->
- Wire data through one searchable picker with live compatibility checks; values drop into prompts as inline chips, and Open PR outputs are always available to later steps.
  <!-- sources: 155,169 -->
- Comfortable editing: multi-select, copy and paste across workflows, 100-step undo, adjustable connection routing, keyboard support.
  <!-- sources: 150 -->
- Trigger a deployed workflow manually with a ticket key or PR link, after preflight checks.
  <!-- sources: 152 -->
- Providers and repositories moved into a compact Source scope bar with an edit dialog.
  <!-- sources: 177 -->

### Trust, migration and replay

- Workflows are validated while you edit and again before deploy; invalid blocks are flagged in place with precise errors.
  <!-- sources: 135,154 -->
- Replay any run visually: the exact path taken and each step's inputs and outputs, live while it runs; data is scrubbed of secrets and kept for 30 days.
  <!-- sources: 149,178,181 -->
- Guided v1-to-v2 migration with preview; your current workflow stays live until you deploy the converted one, and each agent keeps its model.
  <!-- sources: 153,158 -->
- Loop iterations and parallel reviewers are isolated, so they cannot disturb each other.
  <!-- sources: 172 -->
- Runs that fail to start are auto-recovered within minutes, and duplicate runs are prevented.
  <!-- sources: 168 -->

### Harness Profiles

- A profile pins provider, tool version, model, capability settings and skills; published versions are immutable, so agent behaviour never drifts silently.
  <!-- sources: 147,171 -->
- A dedicated studio manages profiles end to end: version history, restore, duplicate, archive, and visibility into which workflows use each version.
  <!-- sources: 160 -->
- Import skills from GitHub in bulk, pinned to an exact commit.
  <!-- sources: 161,162 -->
- The model picker reflects live, auto-refreshed discovery of what the pinned tooling actually supports.
  <!-- sources: 185,187 -->

### Multiple repositories

- One ticket can span several repositories: the agent picks the right one, asks with ranked candidates when unsure, pulls in discovered dependencies, and opens one PR per changed repository.
  <!-- sources: 159 -->
- Pin up to 8 repositories (GitHub and GitLab together) to a workflow; the "which repository" question disappears.
  <!-- sources: 170 -->
- Every PR and MR a run opened is linked from the run, in the dashboard, trace view and Slack.
  <!-- sources: 188,189 -->

### Agent memory

- The agent's memory moved out of your repositories into the platform, with a browser in the dashboard; no more helper files in your codebase. Runs can also mix GitHub and GitLab repositories.
  <!-- sources: 166 -->
- With memory on, the agent keeps per-repository and per-organization knowledge (commands, layout, lessons from past runs), so later runs start smarter; off by default, admins can browse and delete entries.
  <!-- sources: 182 -->
- Everything the agent publishes is scrubbed so internal bookkeeping never leaks into PR bodies, reviews or questions.
  <!-- sources: 190 -->

### Reviews after the pull request

- Human review comments steer the right run: one review starts exactly one follow-up, "Request changes" is detected reliably on GitHub and GitLab, moving the ticket back to the AI column applies the feedback, and the agent ignores its own comments.
  <!-- sources: 165 -->
- New "Reviewed ticket" template: three parallel AI reviewers, a verdict branch, up to three automatic fix retries.
  <!-- sources: 174 -->
- New "Post-PR review" template: reacts when a PR is ready or updated, posts one combined review, and reports pass or fail as a real provider check.
  <!-- sources: 176 -->

## Improvements and fixes

The common theme: statuses tell the truth.

- Finishing runs are no longer cancelled by Jira board automation, and completed runs are recorded as completed.
  <!-- sources: 148,173 -->
- Failed and blocked runs show their real reason, and steps are never silently dropped.
  <!-- sources: 167 -->
- Answered clarifications no longer leave workflows locked.
  <!-- sources: 191 -->
- An outage at one provider (for example GitLab) no longer disturbs runs on the other.
  <!-- sources: 175 -->
- The implementation agent no longer self-publishes changes or mislabels failures.
  <!-- sources: 183 -->
- Reviews on platform-authored PRs complete correctly even where the provider forbids self-approval.
  <!-- sources: 180 -->
- A rejected AI review routes to the request-changes path instead of failing the whole workflow.
  <!-- sources: 179 -->
- Production stress-test hardening: a working Approvals page, no silently skipped tickets, full error text, no phantom "running" runs.
  <!-- sources: 192,194 -->

## Do you need to do anything?

No. Existing workflows keep running unchanged, migration to the new editor is optional, and agent memory stays off until enabled for your environment.

## Known limitations

Visual replay covers runs started after this release. Agent memory rolls out gradually and can be switched off at any time.
