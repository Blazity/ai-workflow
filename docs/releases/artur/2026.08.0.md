# AI Workflow — 2026.08.0

## Highlights

This release makes AI Workflow noticeably more dependable and easier to follow. The agent can now work across several repositories in a single task, keeps what it learns about your projects between runs (without leaving helper files in your code), and every pull request a run opens is now linked directly from the run. On top of that, a large round of reliability fixes makes run statuses more truthful and the whole pipeline steadier under load.

## What's new

- The agent can research and deliver changes across multiple repositories in one task, publishing the related changes to each affected repository.
  <!-- sources: 159 -->
- The agent's working memory now lives outside your repositories, so runs no longer leave helper files in your codebase.
  <!-- sources: 166 -->
- Workflows can be pinned to specific repositories, so every run targets the right codebase instead of guessing from the ticket text.
  <!-- sources: 170 -->
- Choosing which sources a workflow uses now happens in a clearer, dedicated dialog in the dashboard.
  <!-- sources: 177 -->
- The agent builds up knowledge per repository and per organization, so future runs benefit from what earlier runs learned. This can be switched off at any time.
  <!-- sources: 182 -->
- Every pull request or merge request a run opened is now listed on the run itself, so all related changes are in one place.
  <!-- sources: 188 -->

## Improvements and fixes

- Fixed a race where Jira board automation could cancel a run that was just finishing its work.
  <!-- sources: 148 -->
- Run failures are reported truthfully, and deployments keep every step visible instead of silently dropping some.
  <!-- sources: 167 -->
- Runs that reach review now record their real outcome instead of an optimistic status.
  <!-- sources: 173 -->
- A temporary outage of GitHub or GitLab no longer disrupts unrelated work; the system rides out a single-provider outage.
  <!-- sources: 175 -->
- The implementation agent no longer publishes changes on its own and no longer mislabels failures.
  <!-- sources: 183 -->
- Repository labels on run links are shorter and easier to scan.
  <!-- sources: 189 -->
- Agent memory is scoped more carefully and is always scrubbed from any text the agent publishes.
  <!-- sources: 190 -->
- A broad round of stability fixes found while exercising the platform in production ahead of this release.
  <!-- sources: 192,194,195 -->

## Do you need to do anything?

No. The update is applied for you and no configuration changes are needed on your side.

## Known limitations

No known user-facing limitations.
