# integrations/

Every third party the product talks to is one package here, compiled into
every build; a deployment decides which are connected and enabled.

To write one, read [docs/architecture/integrations.md](../docs/architecture/integrations.md)
and start with:

```sh
pnpm run new:integration -- <id> --name "Display Name"
```

## What is here

| Directory | What it is |
|---|---|
| `sdk/` | `@integrations/sdk`: the contract. Manifest types, the context an integration is handed, one port per capability, and the conformance check. Browser-safe. |
| `host-ui/` | `@integrations/host-ui`: the primitives an integration's dashboard pages are built from, and `defineIntegrationDashboard`. |
| `registry/` | `@integrations/registry`: generated by `pnpm run gen:integrations`, never edited. Its conformance suite covers every package in this directory. |
| `_template/` | What `new:integration` copies. Never registered, never shipped. |
| `_fixtures/demo/` | A provider with no network, registered only when `INTEGRATION_FIXTURES` is set at generation time (CI and demo). |
| `arthur/` | Agent tracing in every sandbox, per-run state, a prompt-injection block, a page with data. |
| `slack/` | Messaging: run notifications in one thread per ticket, and a slash command. |
| `gitlab/` | Version control, chosen per repository, on a self-hosted host. |
| `github/` | Version control through a GitHub App: a credential that is not a token. |
| `jira/` | The issue tracker a deployment runs its board on. |

The built-in memory provider is not here: it needs core's database, so it lives
in `apps/worker/src/memory/builtin/`.
