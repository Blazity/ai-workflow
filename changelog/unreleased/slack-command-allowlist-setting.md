- Who may run the `/ai-workflow` Slack command is now a setting: change it on the dashboard Settings page (Integrations) or with the MCP `settings.set` tool, and the next command uses it without a redeploy. `SLACK_ALLOWED_USER_IDS` is still read until a value is saved, and changing the list never interrupts a run that is posting to Slack. Each user id is its own entry: an entry that is blank or holds a comma is refused, since it would lock everyone out or let everyone in. If a Slack connection was stored with an allowlist before this change, the Slack card says that value is no longer used and where to set it.
- The `/ai-workflow` Slack command answers on a deployment that set only `SLACK_SIGNING_SECRET`. When a command cannot be completed, only the person who typed it sees the answer, with a reference an admin can look up in the worker's log, and Slack messages about a GitLab merge request call it an MR.
