- Jira is now an integration. Connect it on the Integrations page or keep the environment variables you already have: the site, the token, the project key, the webhook secret and the three transition ids are read under exactly the names they had, Jira keeps calling the same URL, and the columns you edited on the Settings page are the same columns. Nothing to do on deploy day.
- This deployment can now run with no issue tracker at all. Until now the site, the token and the project key were required to boot, so a deployment that only watched pull requests still had to name a Jira. Anything that needs a ticket now says so where you are standing, rather than the whole worker refusing to start.
- Because those values became optional, a project key with a typo in it would have gone from a loud failure at boot to silence: every delivery ignored as belonging to another project, with nothing to see. The Integrations page now checks it. A project this account cannot see reads Down and says which of the two is wrong.
- The Integrations page also checks whether a Jira webhook actually points at this deployment, whether it is switched on, and whether it sends issue updates. A deployment running entirely on the slower poll because somebody disabled the webhook months ago is now visible instead of merely slow.
- An issue tracker has to be able to say which account it is acting as. That is what separates this product moving a ticket itself, when a run finishes, fails or parks, from a person dragging it out of the AI column. It was optional before, and a tracker that could not answer failed silently in the worst possible direction: every run cancelled the moment it finished, with every log line reading as though a human had done it. A tracker that cannot answer is now refused, and one that is merely unreachable at that moment is recorded as unknown and treated as a person, which is the safe direction.
- The webhook and the poller stopped composing Jira queries. They ask for the tickets in a column and for tickets matching some words; Jira builds its own query. A JQL template you wrote on an Investigate block is still yours and is still passed through untouched, and a tracker that cannot read JQL ignores it and searches on the words instead of finding nothing.
- The Investigate block now talks about an issue tracker and chat rather than about Jira and Slack, on the card, in the editor and in what it reports. Definitions you already saved keep working and keep drawing correctly; they are rewritten when you next publish them.
- Sentences about your tracker now use your tracker's name. "Ticket left the AI column ... via Jira webhook" still says Jira, because that is what your Jira calls itself, not because this product has the word written into it.
