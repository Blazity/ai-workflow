- An agent working on repositories is given the repository map up front: what is checked out and what it may change, what is one relationship away, what was already decided and must not be requested, and one line for the rest of the catalog, each in the description an operator wrote on the Repositories page. Only a planning pass that can actually take another repository is invited to ask for one.
- When a ticket names a repository and the catalog relates it to one or two others, the run opens those too, read only, and the Decision Trail records which relationship brought each one in.
- Delete that relationship on the Repositories page and the next run stops opening the repository: the entry it wrote is removed and the Decision Trail says the relationship is gone. Nothing attaches itself forever after the reason for it was taken away.
- A repository a run has already refused stops being offered to the passes that follow it, with the reason on its line, so the same request is not made and refused twice.
