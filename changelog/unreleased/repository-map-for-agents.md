- An agent working on repositories is given the repository map up front: what is checked out and what it may change, what is one relationship away, and what is already decided or already refused and must not be requested, each with the reason on its line, plus one line for the rest of the catalog, each in the description an operator wrote on the Repositories page. A repository the run is only reviewing is described there once, with the path it is checked out at, the pull request and the commit under review, and read only access to it. Only a planning pass that can actually take another repository is invited to ask for one.
- When a ticket names a repository and the catalog relates it to one or two others, the run opens those too, read only, and the Decision Trail records which relationship brought each one in. Delete that relationship on the Repositories page and the next run stops opening the repository: the entry it wrote is removed and the Decision Trail says the relationship is gone. Nothing attaches itself forever after the reason for it was taken away. Each trail line says what was known when it was written: a repository put in the workspace is recorded as being in the workspace, and what may be done to it is the map's answer.
