- A planning run that asks for a repository it cannot have costs one extra pass and then plans with the repositories it does hold, writing what it could not do without the others into the plan: each one named, with the agent's own reason for wanting it and the run's reason for refusing it. A ticket naming four repositories where somebody answered "just the API" ends with a plan for the API.
- A plan carries the list of repositories it means to change, narrowed to the ones this run actually holds, so the implementation stage knows where the work goes rather than guessing.
- When every repository a plan means to write to is one the run was refused, the run still delivers the plan and the list of what was missing, and stops saying it could not do the work without repositories it was not given, and what to do about it. The ticket comment carries that whole, with the repository, the reason and the action together.
- Every such reason names a move that actually works: the Repositories page, this work's repository list, or the provider. A run proposes selecting or enabling a repository only where that is something a person can do.
- The planning prompt says on the pass that binds that this is the last pass a repository request buys, and when a clarification round is shortened to fit, it says which part was shortened and by how much.
