- The API and MCP serve what an agent was sent: a run's sends with their briefings, each section's text page by page, its parts and their origins, the repositories the send described, and the sources the prompt could not resolve. A dashboard and an MCP client read the same bytes.
- `work_scope.get` can now return a subject's repository questions as rounds, with each answer as it arrived and what the record did with it. It is off unless asked for, so a client that has been calling the tool keeps today's answer.
- Editing a workflow, you can ask a block what it last sent without going to find the run: the newest briefing that block produced, from whichever run and whichever version of the definition produced it, or the reason there is none (it has never run, the run predates capture, capture was off, retention took it, or the block sends no prompt at all). Also `workflows.node_briefing` over MCP.
- A run's briefings now come with what its capture did: how many sends were kept, how many were made while capture was off, refused, lost, or met a briefing already stored. "Eleven sends, two refused" is readable without opening anything, so a gap in what a run kept is visible at a glance.
- `runs.briefing` rides the ordinary read scope, so a token minted for dispatch now also reads what the prompts carried: ticket bodies, `AGENTS.md` and the memory a run was given. Nothing new has to be granted, and nobody who issued a read token was asked about this: review the tokens you have out if that matters to you.
