- Memory is a capability now, and the store this build ships is one provider of it. Nothing changes for a deployment that connects nothing: the built-in store keeps everything it already holds, under the same addresses, with no migration and no switch to flip. What changes is that a memory engine can be connected in its place, and that core no longer speaks in documents and versions when it asks what a run learned.
- A run that could not reach memory now says so on the run itself, not only in a log line. Until now a run that started without the notebook an earlier run left, or compiled a prompt without what a repository knows, looked exactly like the first run on a fresh subject. Three moments are recorded: the workspace it started in, the facts it could not seed, and the prompt it went in with.
- The memory screen no longer shows a store it could not read as an empty one. A provider that is away says why; a provider that serves runs but cannot list what it holds says that instead, and a listing that is not everything the provider holds says so above the table, so a document missing from it is not mistaken for a document nobody stored. That last notice now also appears on the store this build ships, which lists at most a hundred documents at a time and never used to admit it.
- Opening one document that could not be read says the read failed, and says nothing was deleted. It used to say the document was no longer stored, which is the one sentence that sends somebody looking for a deletion nobody made. A document that really is gone still says so.
- Three new MCP tools, `memory.list`, `memory.get` and `memory.forget`, are the same three actions the memory screen offers. An agent that learned something false could not take it back over MCP before; it can now, under the same two roles the dashboard requires for a delete.
- A retraction now costs only what it named. A run that proves one stored line false used to be able to take a document stored under an older, larger cap down to today's bound at the same time. Forgetting on request never removes more than what was asked for; a later run that actually adds something still trims.
